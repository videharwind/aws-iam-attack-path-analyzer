How to use

Step-by-step instructions for running local analysis and scanning AWS environments.

Choose your path

1. Try the sample (no AWS needed)

Explore privilege escalation paths in a pre-built lab snapshot immediately. No cloud account or credentials required.

2. Analyze your own AWS account

Collect IAM configurations from your real environment using a read-only script, then load the generated JSON snapshot offline.

Setup

Follow these numbered steps in your terminal to initialize and run the analyzer locally:

  1. Create a Python virtual environment:

    python -m venv .venv

  2. Activate the virtual environment:

    .venv\Scripts\Activate.ps1

  3. Install required dependencies:

    pip install -r requirements.txt

  4. Run the local API server and UI:

    uvicorn api:app --app-dir src --host 127.0.0.1 --port 8000

    Then open 127.0.0.1:8000 in your web browser.

Scan your own account (optional)

Run the collector script to export IAM state to a snapshot file:

python src/collect.py --profile <your-profile> --region us-east-1 --prefix test --out snapshots/mine.json

Parameters: --prefix test filters identities whose names start with "test". To scan every identity across the entire account without name filtering, use an empty prefix: --prefix "". The collector performs strictly read-only AWS API calls (List and Get actions) and typically finishes in 30 seconds or more depending on account size.

Once generated, reload the Analyzer page and select mine.json from the Snapshot dropdown.

Minimal Read-Only IAM Policy

Attach this policy to the identity executing the collector:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "IAMReadOnlyCollection",
      "Effect": "Allow",
      "Action": [
        "iam:List*",
        "iam:Get*",
        "sts:GetCallerIdentity"
      ],
      "Resource": "*"
    }
  ]
}

Tour of the Analyzer page

  1. Snapshot picker & upload: Choose an existing snapshot from the dropdown and click Load, or upload a custom snapshot JSON file.
  2. Summary cards: Displays counts of Users, Groups, Roles, Policies, Can-Assume edges, the active Snapshot name, Account ID, and Created timestamp.
  3. Graph views: Toggle between the "Full graph" (showing all entities and relationships) and "Attack graph" (principals and traversable escalation edges). Use the "Hide policies" checkbox to reduce clutter.
  4. Node details: Click any node in either canvas to inspect its type, name, and full ARN in the details panel.
  5. Identity Explorer: Select an identity from the dropdown, optionally specify maximum hops, and click "Show reachable" to calculate attack paths.
  6. Path highlighting: Click any row in the reachable results table to highlight the specific escalation route in both graph views and view step-by-step hop reasons.
  7. Clear highlight: Click "Clear highlight" to reset node and edge opacity back to default.

Node Group Orange box (#ed8936) IAM group containing users

Node Policy Green dot (#48bb78) Customer or AWS managed policy
Node Service Yellow dot (#ecc94b) AWS service principal (e.g., ec2.amazonaws.com)

Node External Grey dot (#a0aec0) Principal outside scanned account
Edge member-of Solid grey/blue User membership in an IAM group
Edge attached-policy Solid blue Policy attached to user, group, or role
Edge trusted-to-assume Dashed slate Trust policy grants assumption privilege (trust only)
Edge can-assume Thick red Derived escalation path (identity can actually assume target role)

Note on testrole2: In the sample environment, testrole2 appears disconnected in the attack graph because its trust policy delegates trust to an AWS service principal (ec2.amazonaws.com) rather than a user or role identity.

Reading a result

In the sample snapshot, running reachability analysis for testuser2 returns three target roles:

  • testrole3 (1 hop): testuser2 -> testrole3
  • testrole4 (1 hop): testuser2 -> testrole4
  • testrole5 (2 hops): testuser2 -> testrole3 -> testrole5 (or via testrole4)

Direct-trust vs Trust-and-permission: When a role's trust policy explicitly designates an exact principal in the same account (e.g. arn:aws:iam::123456789012:user/testuser2), AWS allows assumption via direct-trust without requiring separate identity-based permissions. When a trust policy specifies a broader target (such as account root, account ID, wildcard *, or an external account), the principal must also hold an explicit sts:AssumeRole identity policy (trust-and-permission).

The analyzer displays the single shortest escalation path for each reachable role.

Troubleshooting

Problem Likely cause Fix
Unable to locate credentials AWS CLI credentials or environment variables are not configured Run aws configure or pass --profile <name> to the collector
AccessDenied Scanning credentials lack required read permissions Attach the minimal read-only collection policy shown above
Empty graph after a scan The --prefix filter matched no IAM entities Rerun collection with an empty prefix: --prefix ""
Upload error message JSON file is not a valid snapshot format Ensure the file was generated by collect.py with schema_version: 1
port 8000 already in use Another process or server is listening on port 8000 Specify an alternate port: --port 8001
Page blank offline The local Uvicorn backend process is stopped Start the server with uvicorn api:app --app-dir src --host 127.0.0.1 --port 8000

Safety notes

  • Localhost only: The web interface binds strictly to 127.0.0.1 and implements no authentication. Never expose port 8000 to public or untrusted network interfaces.
  • Zero AWS writes: The collection script executes strictly read-only API calls (iam:List*, iam:Get*, sts:GetCallerIdentity). It never creates, updates, or deletes cloud resources.
  • Snapshot hygiene: Snapshots record IAM entity names and structure. Custom snapshots generated in snapshots/ are excluded by .gitignore. Never commit real account snapshots to version control.
  • Data sensitivity: While AWS account IDs are not secrets, relationship mappings describe your organizational security posture. Exercise discretion when sharing screenshots.
