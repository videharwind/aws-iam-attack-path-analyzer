About this project

AWS IAM Attack Path Analyzer is a specialized security analysis engine designed to evaluate complex cloud identity topologies and reveal potential privilege escalation vectors. By modeling identities, group memberships, policy attachments, and trust boundaries as a mathematical directed graph, the tool uncovers hidden multi-step assumption paths that could permit low-privileged principals to escalate into administrative or sensitive cloud roles.

A graph-based, deterministic, rule-based analyzer that finds chained AssumeRole paths in AWS IAM. (Not machine learning.)

The problem

In modern enterprise AWS environments, permissions are fragmented across diverse configurations: user policies, group attachments, role trust policies, and customer-managed documents. Chained AssumeRole paths—where Principal A assumes Role B, which in turn can assume Role C—are exceptionally easy to miss during manual audits and standard IAM policy reviews.

How it works

Collect (read-only, needs AWS)
→
Snapshot (JSON file)
→
Graph (users, groups, roles, policies)
→
Attack view (users & roles + can-assume edges)
→
Reachable paths (shortest path with reasons)

The analyzer evaluates escalations using deterministic IAM rules:

First, a trust policy that names an exact same-account identity is sufficient on its own (direct trust). Second, a trust policy designating an account root, an account ID, a wildcard *, or a foreign account also requires the caller identity to possess an explicit sts:AssumeRole identity-based permission. Third, the analyzer synthesizes these factors into traversable can-assume graph edges and computes the shortest escalation path to each accessible role.

Advantages

  • Offline analysis: Works completely offline after a single read-only collection scan.
  • Zero AWS footprint: Never writes to, modifies, or creates resources in your cloud environment.
  • Deterministic & repeatable: Strictly rule-based calculations without stochastic heuristics or hallucinations.
  • Transparent reasoning: Every escalation hop is fully explainable with explicit direct-trust or trust-and-permission evidence.
  • Built-in sample: Includes sample laboratory data so anyone can evaluate the platform without AWS credentials.
  • Snapshot comparisons: Snapshots facilitate historical auditing and planned configuration drift tracking.

Limitations

  1. Results are plausible access paths under a simplified IAM model, not proof.
  2. Explicit Deny statements, Conditions, NotAction/NotResource, permission boundaries, SCPs, session policies and resource policies are not evaluated.
  3. inline policies are not read yet.
  4. Only the shortest path to each role is shown.
  5. Only sts:AssumeRole chains are analyzed (other escalation techniques such as iam:PassRole or PutRolePolicy are planned).
  6. Service principals, "*" and other accounts are never attack-graph nodes.
  7. Customer-managed policies are listed with Scope=Local and AWS-managed policies are picked up from attachments.
  8. The tool does not replace AWS IAM Access Analyzer or a manual review.

Built and tested on a small lab account (2 users, 1 group, 5 roles, 3 policies).

Related tools

  • PMapper: The closest tool to this analyzer; constructs a directed graph of IAM relationships and derives escalation edges.
  • BloodHound: Pioneered the security concept of pre-computing derived relationship edges and finding shortest escalation paths in Active Directory environments.
  • Cloudsplaining: Evaluates IAM policies in isolation to detect privilege escalation opportunities without building an identity relationship graph.
  • Repokid: Uses historic Access Advisor usage data to proactively trim unused permissions rather than evaluating graph paths.
  • IAM-Vulnerable: Provides deliberately misconfigured Terraform IAM scenarios used to test and benchmark security scanners.
  • Rhino Security Labs IAM Privilege Escalation: Authoritative research cataloging diverse AWS IAM privilege escalation primitives.
